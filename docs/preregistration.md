## 1. 주장 범위

본 프로젝트의 결론은 **라벨된 TEP 시뮬레이션 결함 20종, KOSHA GUIDE P 시리즈 28건, 모사 승인자(라벨 오라클 + 본인 수동 30건), mock CMMS** 조건에 부속된다. 실제 플랜트·실제 엔지니어·실제 CMMS에 대한 주장은 하지 않는다(계획서 §1.3, 정의서 §7).

1차 종점은 **H1 하나**다. H2–H6은 2차이며 다중성 보정 없이 각각 보고한다. H1은 세 쌍별 비교를 모두 통과해야 하는 교차-합집합(intersection-union) 검정이므로 세 비교에 다중성 보정을 하지 않는다.

## 4. 설계 고정값

### 4.1 탐지·보정 — 인과적 알람 규칙

| 항목 | 값 |
|---|---|
| 탐지기 | IF(v1 코드) + conformal p-value. AT + conformal은 Should 비교군 |
| p-value | 캘리브레이션 fault-free 창 점수에 대한 split conformal p-value, `p_t = (1 + #{s_cal ≥ s_t})/(n_cal + 1)` |
| **알람 규칙(행동 입력, 인과적)** | 창 t에서 **prefix-BH**: 에피소드의 **검정된 창**(BLOCK이 아니어서 탐지가 호출된 창) 중 0..t의 p-value에 BH(α = 0.10)를 적용하고, **창 t가 그 시점에 기각되면** `alarm_t = true`. 앞선 창의 알람 판정은 되돌리지 않는다(각 창의 판정은 자기 시점의 prefix로 한 번만). `p_adj_t`는 그 시점의 BH 보정값 |
| **BLOCK 창의 prefix 처리** | BLOCK 창은 탐지를 호출하지 않으므로 p-value가 없다. **검정 목록에서 제외**한다: 창 t의 BH 검정 수 m_t = 창 0..t 중 비-BLOCK 창 수. 비기각 자리(p=1)로 두지 않는다. 기각 대안: p=1 자리 — 검정 수를 부풀려 뒤 창의 임계를 불필요하게 낮춘다 |
| 보증(없음) | prefix-BH는 **prefix별 BH를 이용하는 인과적 휴리스틱이며, 누적 기각 집합에 대한 FDR 통제를 주장하지 않는다.** 각 시점의 마지막 가설에 대한 결정만 누적한 집합은 한 번의 BH가 만드는 기각 집합과 다르고, 독립적인 유효 p-value만으로도 α를 넘을 수 있다(예: 참 귀무 2개, 독립 균등 p에서 P(R>0) = α + (1−α)·α/2 = 0.145 at α = 0.10). **H2는 이 규칙이 실제로 기록한 알람의 FDP를 실증 평가**한다. 에피소드 전체 BH(사후)의 FDP는 보정 자체의 점검으로 [보고]하되 행동·H2 판정에는 쓰지 않는다. 조건부·개별 창·결함 유형별 보증은 주장하지 않는다(계획서 §5.2, ST0-19). 온라인 FDR 절차(LORD·SAFFRON)로의 교체는 의존 구조·공통 캘리브레이션 조건 검토 없이는 보증이 되지 않으므로 이번 범위 밖 |
| L0 비교군(B2) | 고정 임계 Z-score: 변수별 |z| > 3(calibration fault-free 평균·표준편차), 창 안에 한 변수라도 초과 샘플이 있으면 알람. 게이트·conformal 미사용 |
| 드리프트 | v1 PSI, critical 임계는 v1 값 유지. 창 t까지의 에피소드 분포 vs calibration 참조 분포(인과적). critical → `model_trust_low` |
| H2 평가 규칙 | 각 창의 알람은 그 시점에 확정한 값 A_{e,t}를 그대로 쓴다. 마지막 시점에서 과거 전체를 다시 BH 처리한 기각 집합으로 덮어쓰지 않는다 |

### 4.5 행동 정책 규칙 [고정] — LLM은 결정하지 않는다

입력(창 t, 전부 인과적): `gate ∈ {PASS, FLAG, BLOCK}`, `drift ∈ {ok, critical}`, `alarm_t`(§4.1), `s`(진단 집합 크기), `g_AB`, `g_C`(§4.3), `q_used ∈ {0, 1}`. 정의: `valid_s = (1 ≤ s ≤ 3)`, `ev_AB = (g_AB ≥ τ)`, `ev_C = (g_C ≥ τ)`. 규칙은 위에서부터 첫 일치.

| 순서 | 조건 | E (실험군) | B1 | B3 | B2 (L0) |
|---|---|---|---|---|---|
| 1 | gate == BLOCK | `undecidable`(탐지 미호출) | 동일 | 동일 | 해당 없음(게이트 미사용) |
| 2 | alarm_t == false | `no_alarm` | `no_alarm` | `no_alarm` | 임계 미초과 → `no_alarm` |
| 3 | drift == critical | `hold`(model_trust_low) | `propose` | 규칙 4 이하 | 임계 초과 → `propose` |
| 4 | valid_s ∧ ev_AB | `propose` | `propose` | `propose` | `propose`(고정 플레이북, C 인용) |
| 5 | ¬(valid_s ∧ ev_AB) ∧ q_used == 0 | `query_more`(한 번에: ¬valid_s이면 과거 방향 확장 창으로 진단 재실행, ¬ev_AB이면 k=10 재검색 — 둘 다 해당하면 둘 다 수행, 비용 c_query 1회) → **규칙 3부터 재평가**(q_used=1이므로 규칙 5는 닫힘, 규칙 4로 제안 가능) | `propose` | ev_AB → `propose`, 아니면 `hold` | `propose` |
| 6 | 그 외 | `hold`(사유: 진단 불확정 / A·B 근거 없음 — ev_C이면 C 조항을 참고 근거로 함께 기록) | `propose` | ev_AB → `propose`, 아니면 `hold` | `propose` |

- **구조적 보류의 조건:** 제안은 `ev_AB`를 요구한다. C(공통) 조항은 참고 근거이며 단독으로는 제안을 뒷받침하지 못한다. 입력은 예측 진단 집합과 검색 결과뿐이며 실제 결함 라벨로 분기하지 않는다. 따라서 예측 집합이 {16..20}에만 걸리면(범위에 A·B가 없음) ev_AB가 거짓이 되어 규칙 5→6으로 간다 — 이것은 정책표의 귀결이다. 반면 "결함 16–20 에피소드에서 E가 실제로 얼마나 보류하는가"는 예측 집합에 1–15가 섞일 수 있으므로 **검증할 관찰**이며 [보고]한다(C-only 보류 비율).
- B2는 탐지·진단·근거 Skill을 호출하지 않는다.
- `query_more`는 창당 최대 1회. t=0에서 확장 불가이면 재검색만 수행.
- 승인자: 라벨 오라클 = 결함 활성 창 제안은 승인, 비결함 창 제안은 거부. 오라클 결과는 `mart.approvals`에 기록되나 §4.4 비용에는 영향 없음.
- **리플레이 narration:** H1·H2·H4 리플레이는 결정론 경로만 실행하고 LLM 서술은 호출하지 않는다(`narrate=off`). LLM은 대화 평가(H5·H6)·데모·수동 승인 30건에서만.

### 5.6 근거성 판정 보정(부록 A, 탐색)
- 본인 라벨 n = 50 + judge 전수. Cohen κ. κ < 0.6이면 PPI 축소 적용을 생략하고 불일치 사례 분석으로 대체.

## 9. 수정 등록 (동결 후 · 결과 확인 전) — Stage 2, 2026-10-20

변경 규칙(문두)에 따라 기록. 두 건 모두 평가 풀 리플레이 전이며 dev 결과만 확인한 상태에서 결정. 원래 동결 문구는 그대로 두고 아래에 변경 사항을 덧붙인다.

### A-1 (ST2-03) 게이트 BLOCK 조건 축소 — 정책에 영향을 주는 변경
- **원문(§4.1·§4.5 규칙 1, Skill 계약 §1.1):** gate ∈ {PASS, FLAG, BLOCK}, 임계는 v1 값(flag 70 / block 30, Stage 2 재보정 과제). BLOCK이면 탐지 없음.
- **변경:** BLOCK = 현재 창의 입력 계약 위반(비유한값·창 누락)만. flatline(calibration에서 변하는 센서가 창 안에서 일정)은 FLAG. PSI·상관 기반 v1 품질 점수는 FLAG까지(임계 = calibration fault-free 4,800창 창 최소 composite의 5% 분위 = 30.0). 탐지는 FLAG에서도 실행. "BLOCK → 탐지 없음" 규칙 자체는 유지.
- **근거:** v1 품질 점수는 센서 품질 문제와 공정 결함을 구분하지 못한다(ST1-04). dev에서 결함 6(A 피드 손실)의 70% 창이 xmeas_1~5 flatline — 실제 공정 상태 — 이며 이전 규칙이면 탐지 불가. 일정한 값만으로 통신·센서 오류와 제어 입력 유지·포화·고착을 구분할 수 없다.
- **한계 기록:** 창 최소 composite가 calibration 창의 99.67%에서 바닥값 30에 집중해 품질 점수 FLAG는 구분력이 제한적이며 PASS를 "품질 충분"으로 읽지 않는다. v1 `compute_psi`는 기준 백분위 구간 밖 샘플을 버린다(구현 결함, 포스트모템 항목).

### A-2 (ST2-04) 드리프트 입력 정의·집계·임계 변경
- **원문(§4.1):** "v1 PSI, critical 임계는 v1 값 유지. 창 t까지의 에피소드 분포 vs calibration 참조 분포(인과적). critical → model_trust_low."
- **변경:** 비기각 히스토리의 기준 분포 이탈 지표로 재정의. (1) 입력 = 창 0..t−1 중 검정·비기각 창의 샘플(알람·BLOCK 창 제외). (2) D = 센서별 open-bin PSI > 0.2(v1 상수 유지)인 센서 비율. (3) critical iff D > calibration fault-free에서 비기각 히스토리 창 수 h가 같은 (에피소드, 창) 쌍의 99% 분위 — 창 위치 t가 아니라 히스토리 크기로 조건화. 히스토리 < 40샘플은 미평가(ok와 분리 보고). 보정은 평가와 같은 파이프라인(탐지기 → LOO conformal p → prefix-BH → 비기각 선택). 새 비기각 창이 없으면 D·임계·판정 불변, `history_age_windows`로 근거의 나이 보고.
- **근거:** 공정 이상 감지와 모델 적용 범위 감시의 역할 구분. 원 정의는 결함(=분포 이동)에도 반응해 규칙 3(drift critical → hold)과 역할이 겹친다. 이는 H1 결과를 바꾸기 위한 조정이 아니며, 원 정의에서 E가 과도 보류로 H1에 실패하는 것도 유효한 결과였음을 인정한다.
- **보증 없음:** h 일치는 정보량을 맞출 뿐 창 구성은 다르므로 critical에 오류율 보증을 주장하지 않는다. 결함에서 critical 비율이 낮아야 한다는 기준을 두지 않으며, 탐지기가 잡은 이동(히스토리에서 제외)·놓친 이동(편입)·지속 알람(동결)에서의 반응은 보고 항목.
- **공개한 dev 결과(run 1–10):** t별 임계(rev 2)에서는 결함 1·6·13 첫 알람 후 critical 89/89/76%, D가 0.327/0.327/0.231로 동결된 채 임계만 하락. h별 임계(rev 3)에서는 9/0/10%, 동결 구간에서 h·D·임계·판정 불변·age만 증가. 정상 3.26%(평가 460 중 15창). 결함 4(prefix-BH 알람률 1.75%; 고정 α 15.25%와 다른 양) critical 6–7%.

### A-3 (S2-06) 확장 호출의 범위 명확화 — 해석 확정(변경 아님)
- §4.5 규칙 5 "창 확장 2배로 진단 재실행"은 진단만 재실행한다. 탐지 conformal은 20샘플 보정이므로 40샘플 입력에 score·p를 내지 않고, 1차 창의 p·prefix-BH 판정이 유지되며 확장 결과는 알람 상태에 다시 반영하지 않는다. 직전 창 BLOCK·확장 구간 입력 위반 시 거부.
