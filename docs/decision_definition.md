# 의사결정 정의서 (Stage 0-G)

**작성일:** 2026-10-18 · **대상:** 가상 고객 케이스 1건 · **표기:** [실측] 데이터·스파이크로 확인 / [가정] 가상 고객 설정 / [설계] 본 프로젝트의 실험 설정 · **전제:** 계획서 v1.1, 결정 로그 ST0-08~19

## 0. 가상 고객

[가정] 연속식 화학공정 1기(반응기–응축기–분리기–압축기–스트리퍼; TEP와 같은 구성)를 운영하는 중견 화학사의 공정 신뢰성팀. 운전은 중앙제어실 운전원이 3교대로, 공정 이상의 원인 판단·조치 결정은 공정 엔지니어(주간 근무)가, 정비는 정비팀이 CMMS 작업지시로 수행한다. 계측 데이터(DCS 히스토리안), 경보 로그, 안전 기술지침(사내 절차서 + KOSHA GUIDE)은 서로 다른 시스템에 있고, 경보 임계치는 DCS에 고정값으로 설정돼 있다. 상시 운전 조건은 1개이며 가끔 생산량 변경으로 조건이 바뀐다.

## 1. 대상 결정

**경보 창(3분 샘플 × 창 크기)마다, 에이전트가 (a) 작업지시 제안을 즉시 올릴지, (b) 보류할지, (c) 추가 조회(다음 창·추가 센서·문서 재검색)를 할지 — 그리고 제안 시 어떤 결함 가설과 어떤 지침 조항을 근거로 어떤 작업지시를 올릴지.**

- [설계] 결정 주기: 리플레이 창 단위(창 크기·보폭은 Stage 1 리플레이어 설정값, 사전등록에서 고정). 결정은 세 신호 — 탐지 conformal p-value(BH, α=0.10), 진단 conformal set 크기, 문서 근거성(인용 조항 존재) — 의 조합 정책이다(H1).
- [설계] 비교 정책: B1 "탐지되면 항상 제안", B2 L0 고정 임계치 규칙. 1차 종점은 행동 비용(§6).
- [설계] 제약: 품질 게이트 BLOCK 창은 탐지를 호출하지 않고 "판단 불가"(Skill 계약 1조). 근거 조항이 없으면 조치안을 내지 않는다(H3, 구조적 보류).
- [실측] 데이터는 TEP 시뮬레이션(결함 20종, 라벨 있음)이며 실제 플랜트가 아니다. 결론 범위는 "라벨된 시뮬레이션 결함 20종"(계획서 §1.3).

## 2. 담당자·실행 시점·승인권자

| 항목 | 내용 |
|---|---|
| 결정 담당자 (AS-IS) | [가정] 운전원이 1차 대응(경보 확인·수동 조작), 공정 엔지니어가 원인 판단과 정비 요청 결정. 야간엔 엔지니어 호출 |
| 실행 시점 | [설계] 창 종료 시점에 결정. 리플레이는 동일 seed·동일 순서(ST0-13 분할) |
| 승인권자 (AS-IS) | [가정] 작업지시는 공정 엔지니어 발행, 생산 영향이 있으면 생산팀장 승인 |
| 승인권자 (To-Be, L1) | [설계] 에이전트 조치안 → 공정 엔지니어가 승인/수정/거부. **승인 없이 작업지시 없음**(통합 테스트로 보장, 0-D 스파이크로 기제 확인) |
| 승인권자 (To-Be, L2) | [설계] 낮은 p-value·단일 원소 진단 집합·근거성 통과를 모두 만족하는 조치안만 자동 발행, 예외는 승인점 ②. 리플레이 승격 규칙만 구현(Should) |
| L3 | [설계] 운전 조건 변경 위임 — 미구현, 문서 1장 |

## 4. 현재 소요시간 (AS-IS)

[가정] 경보 1건당 운전원 확인 2–5분, 엔지니어 호출·원인 판단 20–40분(히스토리안 트렌드, P&ID, 절차서를 각각 열어 확인), 작업지시 작성 10–15분. 경보 폭주(alarm flood) 시에는 건별 판단이 불가능해 우선순위 없는 일괄 확인으로 바뀐다 — KOSHA P-116(경보시스템 관리)이 다루는 상황. 수치는 가정이며 To-Be 효과는 "처리 능력·근거 추적성"으로 보고하고 인건비로 환산하지 않는다.

## 6. 수용 기준 (파일럿)

원칙: 결과 확인 전에 고정(`preregistration.md`, 태그 `prereg-v1`), 상대 비용 단위로 표현, 평균과 꼬리를 분리.

| 레이어 | 기준 | 근거 |
|---|---|---|
| **1차 종점 (행동 비용)** | 3신호 정책의 리플레이 행동 비용 < B1(항상 제안)·B2(L0 규칙) 둘 다. 계수 c_fp=1.0, c_fn=0.3/지연 창, c_hold=0.1, c_query=0.05(계획서 §4.7), 민감도 c_fp ∈ {0.5, 1, 2} 병기. 에피소드 쌍별 차이의 블록 부트스트랩 CI 하한 > 0, 블록 = run id(ST0-09) | H1 |
| **보정 (FDR)** | 평가 에피소드의 정상 창에서 실현 FDR ≤ α=0.10(캘리브레이션 교환가능 가정 아래). 초과 시 원인 분석: 캘리브레이션 대비 시험 창 점수 척도 비교(ST0-19) | H2 |
| **근거성** | 제안된 조치안의 인용 조항이 실제 문서 조항과 일치(citation hit@3)하고, 근거 없는 조치안 0건 | H3 |
| 운영 가드레일 | 승인 없이 발행된 작업지시 0건(통합 테스트), BLOCK 창 탐지 호출 0건 | Skill 계약 |
| 운영 선행 지표 | 알람→조치안 latency, 턴당 토큰·비용(`mart.agent_steps`) 보고. 선행성 미검증 | 계획서 §3.4 |

판정: H1·H2·H3 모두 통과 → **채택 검토** / H1 통과, H2 초과 → **조건부**(분포 변화 원인 보고와 함께) / H1 미달 → **기각**, "해당 비용 구조에서 보류의 이점 없음"으로 보고하고 에이전트 가치는 근거 인용·승인 흐름으로 낮춰 서술(계획서 §1.5). 비용 계수 사후 조정·기준선 약화 금지.

## 7. 이 데이터로 답할 수 있는 질문 / 없는 질문

| 답할 수 있음 (TEP + KOSHA + 리플레이) | 답할 수 없음 |
|---|---|
| 세 신호 정책이 항상-제안·고정 임계보다 지정 비용 구조에서 행동 비용이 낮은가 | 실제 플랜트의 오탐 비용·정비 비용의 절대값 |
| conformal 보정이 시뮬레이션 정상 구간에서 FDR을 지키는가, 운전 조건 변화에서 깨지는가 | 실제 센서 고장·계획 정비 같은 비결함 변동에서의 오탐 |
| 조치안의 근거가 실제 조항으로 추적되는가 | 그 조항이 그 상황에 공학적으로 올바른 조치인가(계획서 §5.2 근거성 정의) |
| 결함 유형별 탐지 지연(주입 기준·분기 기준 두 가지) | 실제 운전원·엔지니어의 채택률·판단 시간 |
| 승인 흐름이 결정론적으로 재개되는가(0-D) | 실제 CMMS 연계의 인증·멱등성·장애 동작 |

## 8. 결정 정의서가 전제하는 가정 요약

[가정] 항목 5건(고객 프로필·조직, AS-IS 소요시간, 승인 권한 구조, 금지 조치의 권한 경계, 운전 조건 단일성)은 가상 고객 설정이다. 실제 고객이면 첫 미팅의 확인 질문지가 된다. [설계] 항목 중 사전등록 대상(창 크기·보폭, 평가 n, 데모 결함 8종, α, 비용 계수)은 0-H에서 동결한다.
